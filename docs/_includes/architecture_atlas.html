Stage 1

Public interface and fit lifecycle

Statistical estimators build one GAM and delegate to it. The core defaults to fixed smoothing; the adapters request REML where it is supported. FitSession.begin clones the family and clears fitted state. commit_to publishes that copy only after the fit returns, so a failed refit leaves the previous result in place.

Stage 2

Formula and canonical specifications

parse_gam_formula turns one formula string into a ParsedGAMFormula. extract_formula_terms turns that parse into the objects the compiler consumes. In y ~ s(x, bs='cr', k=8) + z, s(...) is declarative syntax: one smooth of x and one linear effect of z. No coefficient has been estimated yet. A distributional formula carries one component per linear predictor.

Stage 3

Basis, penalty, and constraint construction

smooths owns the runtime term. splines builds the basis matrix. penalties, constraints, and coefficients supply the roughness penalty, the side condition, and any positive-coefficient map. Knots, factor levels, and those maps become fitted term state and are reused at prediction. A cubic smooth evaluates its columns, builds an integrated-curvature penalty, and centers the basis so it is not confounded with the intercept. Shape constraints identify which coefficient directions must stay positive. That choice is part of the term, before the optimizer runs.

smooths/runtime term splines/basis matrix penalties/roughness constraints/side condition coefficients/positive map

The constructed objects are stored on CompiledTerm. Compilation, in the next stage, places those columns into the model-wide coefficient vector.

Stage 4

Compilation into a numerical model

compile_designs builds one predictor specification per linear predictor and calls compile_model. The compiled model is stored on gam_result_ before smoothing selection or the coefficient solve. compile_design is the fit-free path: it returns a CompiledDesign and does not estimate coefficients. A location-scale model has several predictor designs.

Stage 5

Coefficient fitting and smoothness selection

fit_model_core is the only function the model classes call. With smoothing held fixed, the inner target is the penalized likelihood. Automatic smoothing searches the log smoothing parameters and solves the coefficients again at each candidate. An efs_solution already returned by that search is kept.

−ℓ(θ) + ½ θᵀ Sλ θ

Stage 7

Prediction, inference, and diagnosis

These methods read gam_result_ and the compiled callbacks. They do not build a second basis, and they do not rerun smoothing selection. On the link scale a new row is the fitted basis times the exported coefficients, plus the offset evaluated for that row.

ηnew = Bnew θ̂ + onew
