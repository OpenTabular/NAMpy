tweedie
=======

.. math::

   Y=\sum_{j=1}^NZ_j,\quad N\sim\operatorname{Poisson}\!\left(\frac{\mu^{2-p}}{\phi(2-p)}\right)

* **Natural domains:** :math:`\mu>0,\quad\phi>0,\quad1<p<2`; power is fixed or modeled according to the family contract.
* **Conditional mean:** :math:`\mathbb E[Y\mid x]=\mu`
* **Conditional variance:** :math:`\operatorname{Var}(Y\mid x)=\phi\mu^p`

:math:`Z_j\sim\operatorname{Gamma}\!\left(\frac{2-p}{p-1},\ \mathrm{scale}=\phi(p-1)\mu^{p-1}\right)`

References: `PyTorch probability distributions <https://docs.pytorch.org/docs/stable/distributions.html>`_. NAMpy defines its family transforms and point outputs below.

For power 1<p<2, a Tweedie response is a compound Poisson sum of
positive Gamma jumps. The event count can be zero, creating an exact
zero mass alongside a continuous positive density.

.. math::

   Y=\sum_{j=1}^{N}Z_j,\qquad N\sim\operatorname{Poisson}(\lambda_N),\quad P(Y=0)=e^{-\lambda_N},\quad \operatorname{Var}(Y)=\phi\mu^p.

The zero probability is coupled to mean, dispersion and power; it
is not an independent zero-inflation predictor. p controls the
mean-variance relationship, while phi controls its magnitude.
Estimating power can require numerical density-series evaluation.
Statistical tw can estimate a global power, twlss gives power and
dispersion their own predictors, and the neural interface fixes the
configured power. Their fitting routes are different even though
the compound-law interpretation is shared.

Neural training composes this response objective with the chosen architecture. Its raw outputs pass through the configured domain transforms; likelihood parameterization and network architecture are separate choices.

See :doc:`/statistical_reference/families/theory` for likelihoods,
links, weights and distributional predictors. The mathematical law
does not imply support for every fitting or smoothing-selection route;
the contracts below define the implemented combinations.

Targets, transforms and scoring
-------------------------------

Target shape/encoding: ``(n,) floating scalar response; support follows the distribution definition above``. Network rows must align with target rows. Parameter column order is given in the output contract below. Positive default transforms use ``softplus(raw)+eps``; identity leaves unrestricted locations unchanged. Constructor transform options accept registered transform names or callables and must preserve the stated parameter domains.

``compute_loss`` and ``compute_loss_per_sample`` consume raw network outputs, not already transformed parameters. The scalar loss is averaged over observations. Lower loss is better. LSS scoring follows the shared estimator contract; response SD summarizes conditional variability, not estimation uncertainty. Distribution-specific moments that do not exist cannot be interpreted as finite uncertainty estimates.

Implementation definitions: :mod:`nampy.neural.families`. See the source link on the runtime contract for the implemented transforms and objective.

Neural distribution family for ``family='tweedie'``. Configure its constructor through ``distributional_kwargs`` on an LSS estimator.

Signature

.. code-block:: python

   TweedieDistribution(variance_power: float = 1.5, name: str = 'Tweedie', mean_transform: Union[str, Callable] = 'positive', dispersion_transform: Union[str, Callable] = 'positive', series_max_terms: int = 200, eps: float = 1e-08)

Parameters
----------

Dimensions: ``n`` rows, ``d`` input columns, ``p`` fitted coefficients, ``q`` response/family output columns; ``n_ref`` is the centering-reference row count.

.. list-table::
   :header-rows: 1
   :class: api-reference-table

   * - Parameter
     - Type / input shape
     - Default
     - Description
   * - ``variance_power``
     - ``float``
     - ``1.5``
     - Fixed Tweedie power p in (1,2), giving Var(Y)=dispersion*mean**p.
   * - ``name``
     - ``str``
     - ``'Tweedie'``
     - Display label for this distribution; does not change its mathematical family.
   * - ``mean_transform``
     - ``str | callable(torch.Tensor) -> torch.Tensor``
     - ``'positive'``
     - Transform of the conditional mean column; default identity for an unrestricted mean and positive for a positive mean.
   * - ``dispersion_transform``
     - ``str | callable(torch.Tensor) -> torch.Tensor``
     - ``'positive'``
     - Transform of the positive dispersion column; its variance interpretation is given below.
   * - ``series_max_terms``
     - ``int``
     - ``200``
     - Positive maximum number of terms in the compound-Poisson likelihood series; controls truncation cost and accuracy.
   * - ``eps``
     - ``float``
     - ``1e-08``
     - Positive numerical floor used by positivity transforms and stable logarithms; it is not response noise.

``forward(raw)`` transforms a tensor of network outputs into natural parameters. ``compute_loss(raw, y)`` returns the scalar training objective; ``compute_loss_per_sample(raw, y)`` retains the observation dimension. ``predict_point(raw, transformed=False)`` returns point predictions; set transformed=True only when passing already transformed values.

``predict`` returns family-transformed values; ``predict(raw=True)`` returns network predictors. Shapes and column meanings follow this family’s contract above. ``predict_point`` reduces to the family-defined point functional. Conditional spread is distributional spread, not parameter-estimation uncertainty.
