Adaptive SC B-spline (``scad``)
===============================

Adaptive B-spline constructor branch corresponding to mgcv scad. This constructor does not itself impose shape inequalities.

Theory and interpretation
-------------------------

An adaptive spline allows the strength of smoothing to vary over
the covariate domain. A low-dimensional basis represents the local
penalty weights, producing several positive-semidefinite penalty
matrices rather than one global roughness matrix.

.. math::

   S(\lambda)=\sum_h\lambda_hS_h,\qquad J(\beta)=\sum_h\lambda_h\beta^\mathsf TS_h\beta.

Different penalty components emphasize different regions, allowing
a curve with a sharp feature in one region and a smooth trend elsewhere.
The function basis dimension and the penalty-weight basis dimension
control different kinds of flexibility. Many local smoothing weights
require enough data to identify them; adaptive smoothing is more
demanding than fitting one ordinary P-spline. The two-dimensional
construction extends this idea over marginal directions.

The sc/scad constructor names identify B-spline construction
branches. They do not impose a sign constraint on coefficients or
derivatives. Use an explicit SCOP basis such as mpi for monotonicity.

For coefficient coordinates, centering, null spaces and EDF, see
:doc:`/statistical_reference/smooths/theory`. The formula and runtime
contracts below specify which mathematical options NAMpy exposes.

Formula interface
-----------------

.. code-block:: python

   formula = "y ~ s(x, bs='scad')"

Formula constructors are parsed inside strings; they are not Python functions. ``k``, ``m``, ``by``, ``id``, ``sp`` and ``fx`` configure the term where supported. Formula ``id`` maps to runtime ``smoothing_id`` and ``fx`` maps to ``fixed``.

Parameters
----------

.. list-table::
   :header-rows: 1
   :class: api-reference-table

   * - Formula option
     - Type / shape
     - Default
     - Meaning
   * - ``bs``
     - str
     - ``model basis ('tp' by default)``
     - Select this basis with bs='scad'. The alias basis is also accepted.
   * - ``k``
     - int | sequence[int]
     - ``-1 (automatic)``
     - Function-basis dimension: an integer or one value per margin. Automatic values are 40 in one dimension and 15 per margin in two dimensions; the penalty-basis dimension m must remain compatible.
   * - ``m``
     - int | sequence | None
     - ``None``
     - Number of basis coefficients used to represent the varying penalty: default 5 in one dimension, or 3 per margin in two dimensions. This is an adaptive-penalty dimension, not the polynomial degree.
   * - ``by``
     - str | expression | None
     - ``None``
     - Numeric multiplier or categorical source column/expression defining varying-coefficient or level-specific effects; evaluated on training and new rows.
   * - ``id``
     - str | int | None
     - ``None``
     - Share smoothing parameters across compatible terms. Alias smoothing_id is accepted; basis sharing follows id_links_bases.
   * - ``sp``
     - float | sequence[float] | None
     - ``None``
     - Penalty strengths in term penalty order. Nonnegative supplied values fix strengths; negative entries request estimation when automatic selection is enabled.
   * - ``xt``
     - mapping | sequence[mapping | None] | str | None
     - ``None``
     - Optional marginal basis selection, for example {'bs': 'ps'} (default). Supported alternatives are cp, cr and cc. This is distinct from selecting the outer ad basis.
   * - ``fx``
     - bool
     - ``False``
     - Fit the smooth without its roughness penalty. Model-level null-space selection cannot be combined with a fixed unpenalized term.
   * - ``pc``
     - float | sequence[float] | mapping[str,float] | None
     - ``None``
     - Homogeneous function constraint f(x0)=0. Supply one coordinate per input covariate, or a named mapping; the basis is reparameterized at the point.

The formula compiler resolves defaults independently of runtime constructors. ``knots`` and ``select`` belong to the model, not the formula call. Runtime-only setup options are documented in the implementation API.

Identifiability, penalty and prediction
---------------------------------------

The basis penalty acts on fitted coefficient coordinates; requested rank k is not fitted EDF. Ordinary smooth centering separates the smooth from the model intercept, subject to the basis, numeric/factor by-variable and point-constraint rules. A point constraint replaces the relevant centering direction rather than fixing an arbitrary coefficient. Prediction reuses the fitted knots, constraints and penalty setup.

Out-of-range behavior is basis-specific and follows the retained fitted basis, rather than automatic expansion of its rank or knot domain. For bounded spatial domains and shape constraints, inspect the domain/constraint restrictions in the runtime notes before extrapolating.

Outputs
-------

The formula adds a term to the fitted model's additive predictor. Its coefficient block has p_term columns after constraints; this dimension differs from EDF. ``predict(type='terms')`` returns a floating array with n rows and one column per retained term for a scalar predictor. ``lpmatrix`` returns the full floating model design, shape (n, p), including the other terms. The scalar Gaussian examples below produce response predictions of shape (n,). Runtime matrix and penalty contracts are documented separately.
