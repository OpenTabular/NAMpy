supports_smoothing_method
=========================

.. math::

   \mathcal C(\text{model},\text{criterion})\in\{\mathrm{True},\mathrm{False}\}

A criterion needs more than a family name: it can require a known dispersion, a particular likelihood backend, derivative orders and compatible coefficient/observation transforms. This helper combines those capability checks. For example, known-scale UBRE and estimated-scale Gaussian REML have different prerequisites.

Resolve aliases first with :doc:`resolve_smoothing_method`. The predicate expects lower-case canonical names and does not normalize them. It does not run every design/optimizer compatibility check or fit a model; a True result is a capability indication rather than a convergence guarantee. NCV/QNCV capability also depends on the ordinary-family derivative route, not merely the availability of a neighborhood argument.

Import: ``from nampy.gam.fit.selection import supports_smoothing_method``. These are backend helper APIs; core-model methods remain the usual analysis interface.

Signature
---------

.. code-block:: python

   supports_smoothing_method(model, method)

Parameters
----------

``model`` — Type: fitted core ``nampy.gam.GAM``
   Default: ``required``. Use a fitted core model, or ``estimator.gam_`` from a wrapper. Required compiled/fitted state is read from this object; passing a wrapper directly is not supported.

``method`` — Type: str
   Default: ``required``. Canonical lower-case method: fixed, gcv, gacv, ubre, aic, ubreaic, ml, reml, p-ml, p-reml, laml, ncv or qncv. This helper does not lowercase or resolve aliases; unknown values raise ValueError.

Outputs
-------

``return value`` — Type: bool, shape ()
   Reports this model/family criterion capability, including scale, transformed-coefficient/observation and derivative guards. It does not certify every optimizer, formula composition or convergence condition; fitting performs further validation.
